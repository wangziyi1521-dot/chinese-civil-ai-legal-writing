# T02｜《生成式人工智能服务提供者过错的认定》详细框架

执行日：2026-11-16。输入依据：`acceptance-inputs.md`中预先固定的T02。主模式为框架设计；规范基线复用`research/topics/norms-20261115.md`，本次另打开最高法正式意见及网信办暂行办法原文。以下交付可展开写作的论证框架，中心命题是待正文论证的解释方案。

## 研究问题、范围与题名

可回答的问题是：面向境内公众的生成式人工智能服务输出侵害人格权益的内容时，如何在法定归责框架内，将服务提供者可预见、可控制的具体风险转化为注意义务，并证明该义务受到违反？

原题同时容纳医疗决策、自动驾驶、知识产权、个人信息处理及一般内容输出，事实结构和适用规范差别过大。主线限于文本生成服务输出不实信息侵害名誉权的损害赔偿；隐私和个人信息处理作为规范分流及边界检验，不扩写全部AI应用。研究主体是对涉案生成服务有部署、运营或内容风险控制能力的提供者，开发者与接口调用者分别识别，不能由“提供者”名称包揽产业链。纯粹实物产品缺陷、自动驾驶、合同保证和惩罚性赔偿均不进入主论证。

建议题名：《生成式人工智能不实内容输出中服务提供者过错的认定》。若只写一万字，可进一步收紧为《生成式人工智能侵害名誉权的注意义务与过错证明》。如保留原题，应在引言明示上述范围。

拟论证的中心命题：一般内容输出以一般过错为起点；符合个人信息处理特别规则的案件分流适用第69条。过错标准采用“具体风险—对应措施—违反评价”的结构，通知前的一般义务与通知后的必要措施分别论证。信息偏在通过证据取得和有条件的不利后果处理；过错和因果关系分别证明。

## 引言的两段任务

第一段以控制变量场景提出问题：同一服务编造某人的受贿经历，分别只向本人、向第三人输出；提供者分别在从未收到有效通知、已收到附初步证据的通知后继续输出。说明相同的“虚假内容”会因权利受侵害方式、知悉状态及措施可行性产生不同法律评价，不能从输出错误直接推出赔偿。

第二段以2026年意见已经给出的一般归责顺位为前提，压缩三条学术路径，并把待解问题转向义务内容、通知规则范围和证明方法。交代个人信息处理的特别规则及正文的论证顺序。引言不另立“重大意义”段，不先写摘要。

## 第一章 过错评价的对象与法定归责入口

**问题。** 谁的何种行为受评价？一般内容输出与处理个人信息为何不能共用一项不分条件的归责结论？

**待证命题。** 应先确认被告对涉案生成服务的行为贡献及所涉权益，再选择责任基础。没有明确特别法律规定时依第1165条第1款；符合个人信息保护法第69条的个人信息处理侵权适用过错推定。服务定性只是入口，不能免除对具体控制事实的证明。

**细化提纲。**

1. 生成行为的归属：区分训练材料提供、模型开发、服务部署与用户输入，列出被告控制的模型版本、检索来源、输出和处置机制。
2. 权益与请求权：主线为向第三人输出不实事实造成名誉损害；个人信息处理须另审处理者身份、处理行为和个人信息权益，不能把一切提及自然人的内容自动归入第69条。
3. 归责顺位：法定特别规则→一般过错；过错推定仍以过错为可反证的责任条件，无过错责任另须法律根据。
4. 研究的前提筛选：仅本人接收、事实与意见、未发生可赔损害等情形，应在侵害及损害环节处理，防止过错章节替代全部成立要件。

**必要性与方法。** 以请求权基础、主体及行为分型确定后文究竟要证明什么。没有本章，注意义务清单会混用一般责任和特别法证明规则。

**具体材料。** 现行法律：民法典第1165条第1、2款、第1166条；个人信息保护法第69条。司法指导文件：2026意见（三），以及（七）与（九）的场景分工。文献：C05程啸，正式全文第5—14页关于行为归属、第14—18页关于名誉侵害；C10朱晓峰，正式全文第89—93页关于处理者与其他行为人的区分。这里只使用已核到的作者论证，不转引尚未回源的判例。

**最强反方及回应任务。** 生成模型不受逐次语句控制，输出应归于用户或系统。回应须证明特定被告的组织与技术控制如何连接到所评价行为；不能仅以系统无法承担责任便倒推某一企业承担责任。

**预期小结与承接。** 得到一般输出与个人信息处理两条分流路径，并固定主线被告及行为。第二章据此回答该被告负何种义务。

## 第二章 注意义务的来源、保护范围与阶段差别

**问题。** 行政管理要求何时能转化为民事过错标准？收到通知前后，义务是否相同？

**待证命题。** 规范提供的义务须经过保护目的、主体和权益范围筛选；对抽象“不得侵权”的重述，仍需具体化相应行为要求。通知后的必要措施具有明确规范支点；通知前独立义务的范围需结合一般过错与第（七）项的关系作解释。

**细化提纲。**

1. 法定义务的筛选：分别辨识保护国家公共利益、服务用户和被内容涉及第三人的规范，说明受害人及损害是否落入保护范围。
2. 行为要求的具体化：把数据质量、内容可靠性、投诉与处置要求转换为可观察的评测、风险提示、核查或限制措施；每项均交代目的、触发事实及适用场景。
3. 通知前的一般防范义务：以已知风险类别、提供者作出的能力表述、输出面向及合理可行措施为论证变量，避免设定“任何错误均不得发生”的结果义务。
4. 通知后的必要措施：依2026意见（七）审查通知中的初步证据、身份信息、到达时间及相应措施；既有内容处置与防止同类再次生成分别评价。
5. 第（七）项的竞争解释：其通知条件是特定责任路径的成立条件，还是一般内容输出赔偿的统一前提？分别检验文义、体系和规范后果后作结论；不能由该项未明确写出的内容直接推出全面豁免。

**必要性与方法。** 先有相关义务才有违反评价。保护目的解释负责连接行政义务与私法责任，体系解释负责处理一般条款和通知路径；二者不能由“公私法协同”口号代替。

**具体材料。** 民法典第1165条及2026意见（七）。部门规章《生成式人工智能服务管理暂行办法》（国家网信办等七部门令第15号，2023-08-15施行）第2、4、7、9、14、15、17、22条；各条仅在自身适用范围内使用。C11徐伟，已读完整转载正文第二至四部分；C05第四部分（二），原刊第19—20页；C06程啸仅摘要，支持“法定义务需经保护个人目的及主体、事项范围筛选”的摘要命题，不能代替全文论证。C03第三部分的通知类推方案与C05第二部分构成竞争解释；须注明均形成于正式意见发布前。

**最强反方及回应任务。** 第（七）项将通知写为条件，通知前不承担民事赔偿才能保留审慎包容空间。回应应区分该项具体场景与第（三）项的一般过错，并检验通知前是否存在具体且相关的独立义务；如无法证成，应收缩该部分责任范围。

**预期小结与承接。** 形成按风险和阶段列明的候选义务及保护范围。第三章再判断措施做到什么程度才算履行。

## 第三章 合理注意程度及技术发展抗辩

**问题。** “现有技术水平”是怎样的比较基准？行业平均合规或完成备案是否足以证明无过错？

**待证命题。** 过错按侵害行为发生时的合理可行措施评价。行业通常做法、个别企业能力和潜在先进技术分别进入证据评价；技术不可能性可以限制具体措施义务，但自称技术黑箱或完成备案均不能包办无过错判断。

**细化提纲。**

1. 评价时点：锁定涉案版本与行为发生时，防止事后技术倒推，也防止忽略反复通知后可用的新措施。
2. 比较对象：从同类用途与风险出发确定合理提供者；区分行业最低要求、通行措施及具体企业已掌握的风险信息。
3. 风险与成本配对：就某项措施说明可预见损害的严重性、影响范围、可减少的风险、误伤与实施成本；不把企业整体盈利或规模直接改写为不同归责原则。
4. 技术措施的充分性：比较纯参数输出与联网检索；“附网址”还须审查其可访问性、可靠性及是否支持涉案断言，不能把网址存在等同于准确核实。
5. 合规与残余义务：备案材料只能证明其实际载明的事项；履行行政程序与涉案时点已尽合理注意分别取证。

**必要性与方法。** 把第二章的义务转化为可反驳的行为标准。以条件变化检验标准，避免“技术特殊性”同时被用于加责与免责却没有判断尺度。

**具体材料。** 2026意见（三）的多因素标准；暂行办法第4条第5项及第17条。C03第二部分（三）（四），已读全文转载但无脚注页界；C11第四部分关于技术基准与防范成本；C05第19—20页；C18王若冰仅摘要，限于摘要可见的现有技术标准，不还原其章节或细部抗辩。

**最强反方及回应任务。** 行业基准会使领先企业因无人能超过自己而永不构成过失；最佳技术基准又会把新技术变成强制义务。回应应选择“当时合理可得、与具体风险对应的措施”，并用最高水平系统未采取低成本已知防护的反例检验。

**预期小结与承接。** 给出措施义务、合理程度及可反证事实。第四章据此列明各方需要提供何种证据。

## 第四章 过错证明与信息偏在的程序回应

**问题。** 一般过错下受害人如何获得内部材料？证明困难在哪些条件下引发不利后果？

**待证命题。** 应分别处理义务违反的事实推认、法定过错推定和证明妨碍。个人信息保护法第69条只在适用范围内配置过错证明责任；一般内容案件先利用现有取证、保全及证据控制规则，不能仅因黑箱而倒置全部要件。

**细化提纲。**

1. 外部证据入口：固定输入、输出、时间、版本、输出对象及通知过程，指明哪项风险防护可能缺失；受害人无需在起诉时还原模型全部机理。
2. 内部材料及对应事实：风险评测对应可预见性，版本和措施记录对应履行状态，日志对应生成与通知处置；对材料的需要必须具体说明。
3. 证据取得：依2026意见（十七）提出调查收集、保全和技术事实查明请求；控制证据且无正当理由拒不提交时，结合民事证据规定第95条审查不利主张是否可被认定。
4. 法定负担与事实推认：一般输出案件依取得的证据判断违反；个人信息处理者依第69条证明无过错。列明推认的基础事实和可反驳方式，避免将客观证明责任转移藏在“违法推定过失”用语中。
5. 商业秘密和个人信息：限定所需材料与争点的关系，研究保密、局部提交等可行安排；具体程序条文及技术标准列为正文写作前补核项。

**必要性与方法。** 第三章给出标准，本章解决标准如何得到证明；若没有本章，合理注意的实体方案可能无法为受害人使用。

**具体材料。** 个人信息保护法第69条；民事证据规定第95条（2019修正、2020-05-01施行）；2026意见（十七）（十八）。C07林洹民第三部分，完整转载正文但无脚注；C15朱晓峰仅选编，不能标成已读全文；C12徐伟、徐涵渊第三部分及结语，完整转载缺原刊脚注，使用其分层条件作反例检验，不把拟议因果推定当现行法。

**最强反方及回应任务。** 黑箱同样约束企业，举证协力也无法发现全部生成原因；过度提交资料会转化为责任压力。回应要区分“既存可提交材料无法获得”和“技术上尚不能解释的机制”。后者不当然构成拒证，前者应先审查控制与拒绝理由。

**预期小结与承接。** 得到可实行的证明步骤及剩余困难。第五章据此确认过错成立后仍需哪些要件，检验救济是否真实改善。

## 第五章 因果关系、损害及责任范围的边界检验

**问题。** 已认定违反注意义务，为何还不能直接判赔全部损失？用户恶意诱导及信息再传播如何影响责任？

**待证命题。** 义务违反只解决过错相关判断；仍须证明受保护权益受侵害、损害及与被告行为的因果联系。用户行为与提供者行为分别评价，通知后未采取措施尤其需要识别由该遗漏造成的损害范围。

**细化提纲。**

1. 四组可否证场景：仅本人接收；向第三人输出；用户恶意诱导；有效通知后持续生成。分别检验侵害、过错、因果和损害，而不以一个结论覆盖全部要件。
2. 义务保护目的与因果：若违反的要求与涉案风险无关，不能仅依行政违规认定全部损害可归责。
3. 多因与多主体：固定各方可控制的行为和损害贡献，再讨论责任形态；现有材料尚未完成的多数人条款核验，不预写连带或按份结论。
4. 证明救济边界：C12条件化因果推定是规则建构；C10第97—100页的特定致害人不明补偿是解释方案。先说明未知的是因果事实还是具体致害人，再比较方案。
5. 给出判定顺序表：主体与行为→权益及侵害→法定归责入口→义务和违反→证据评价→因果及损害→责任范围。

**必要性与方法。** 用反例和法律效果审查前四章是否把过错认定扩张成结果责任；本章为主线的边界检验，不另写一般因果关系理论。

**具体材料。** 民法典第1165条“造成损害”的要件表达；个人信息保护法第69条第1、2款；2026意见（七）（十七）。C05第14—20页；C10第三部分（二）第97—100页；C12第三部分和结语。第1186条及第1254条补偿类推仅在专节作为学术方案介绍，不能写成黑箱案件可直接公平分担的现行规则。

**最强反方及回应任务。** 逐项证明仍会使受害人无法获赔，应统一结果责任。回应须具体说明哪些困难已由材料取得、法定推定和通知路径解决，哪些尚存；剩余不足可支持有限立法建议，但不能替代当前法律的适用条件。

**预期小结与承接。** 评价框架能够区分同样错误输出的不同法律后果。结论据此前提回答研究问题，并准确列明尚需制度补充的证明缺口。
